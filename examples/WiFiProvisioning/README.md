# Wi-Fi設定サンプル

ESP32 Arduino core 2.0.17で、表示名と1件のWi-Fiを保存する最小のアプリです。M5、センサー、MQTTには依存しません。保存とAP資格情報にはそれぞれ`ac_demo`、`ac_demo_id`名前空間を使用します。

1. `pio run -e esp32_provisioning_example`でビルドします。実機への書込みは利用するポートを確認して別途実施します。
2. USBシリアルを115200bpsで開き、`i`を入力するとAPのSSID・パスワード・Wi-Fi QR用文字列を取得できます。通常ログには秘密値を表示しません。
3. スマホを表示されたWi-Fiへ接続し、通常ブラウザーで`http://192.168.4.1`を開きます。自動ログイン画面はブラウザーを開くための案内だけを表示します。
4. 表示名とWi-Fiを入力して保存します。HTTPの受付後に、loopが接続試験を開始します。IP取得に成功した場合だけストアへ確定し、15秒後に再起動します。
5. 再起動後もサンプルはAPを開きます。保存済み表示名・SSIDを確認でき、パスワードは返しません。接続試験に失敗した場合は保存済み設定を維持します。

同一サブネットやチャネル変更でスマホが切断された場合は、デバイスのWi-Fiへ接続し直してください。接続できない間にページを閉じても、受付済みジョブはloop側で進行します。読み出し異常では上書きせずUSBでの調査を必要とします。

AP資格情報は初回のみ生成し、通常のファーム更新では維持します。NVS全消去で資格情報を失った場合は、再生成後にUSBで読み出してQRラベルを再発行してください。破損時には自動再生成しません。製品での物理ボタン条件・復旧コマンド・運転モードは利用側へ追加してください。

`application.js`が製品相当の表示名と保存ジョブを担当し、Wi-Fiフォームは共通の`WiFiForm`を利用します。`tools/build_provisioning_example.py`が共通CSS/JSとアプリHTML/JSを結合し、外部依存のないgzipとPROGMEMヘッダーを生成します。

実機のWi-Fi・電源断・iOS CNAの試験は、ホストテストやビルド成功とは別に実施してください。
